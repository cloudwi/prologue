# 첫 연결 캠페인 실행안

2026-11-04. 목적은 설치 수를 늘리는 것과 함께, 신규 참여자가 실제 소개와 답장을 경험하는지 확인하는 것이다. 아래 문구는 게시용 초안이며 외부에 발행하지 않았다.

## 전달할 가치와 적용 상태

**사진보다 생각을 먼저 알아가는 소개팅, 프롤로그.** 질문에 답하고 소개 가능한 상대의 생각을 읽는다. 마음이 가면 연락처를 담은 편지로 이어간다. 가입·문답은 무료이며 편지 등 일부 기능은 잉크를 사용한다. 소개 가능한 상대가 없으면 기다릴 수 있다.

가입 없는 문답 체험과 가입 이어가기는 로컬 구현 상태다. 웹·백엔드 배포와 앱 출시를 확인한 다음 해당 기능을 홍보한다. 체험 답변은 예시이며 실제 회원이나 실제 소개 건수로 세지 않는다.

## 프로필과 게시물 문구

### 인스타그램·스레드 프로필

사진보다 생각을 먼저 알아가는 소개팅.
하루 한 문답, 마음이 가면 편지로 이어가요.
아래 링크에서 문답 방식을 체험해보세요.

체험 배포 후 프로필 링크:
`https://prologue.day/?utm_source=instagram&utm_medium=organic_social&utm_campaign=first_connection#try`

스레드에서는 `utm_source=threads`로 바꾼다.

### 게시물 1 — 질문으로 시작

쉬는 날에는 주로 무엇을 하나요?

밖에서 새로운 곳을 찾는 사람.
집에서 좋아하는 일을 하는 사람.

같은 질문에도 다른 하루가 담겨요.
당신은 어떤 답에 마음이 가나요?

사진보다 생각을 먼저 알아가는 소개팅, 프롤로그.
프로필 링크에서 문답 방식을 체험해보세요.

이미지는 질문과 두 선택지만 담는다. 앱 체험 화면의 답변을 함께 쓸 경우 '예시 답변'을 명시한다.

### 게시물 2 — 실제 이용 과정

질문 하나에 답하고,
소개 가능한 상대의 생각을 읽어요.
마음이 가면 한 통의 편지로 인사를 건네요.

답변에서 시작하는 소개팅, 프롤로그.

화면 영상은 체험 선택 → 예시 답변 → 프로필 → 편지 안내 순서로 짧게 만든다. 실회원 정보와 연락처는 넣지 않는다. 연락처는 답장으로 서로 교환하는 현재 규칙을 그대로 안내한다.

### 게시물 3 — 첫 편지 예시

“쉬는 날 걷다가 작은 가게를 발견하는 걸 좋아하신다는 답이 기억에 남았어요. 저도 목적지 없이 걷는 날이 좋아요. 최근에 찾은 곳 이야기를 듣고 싶어요.”

멋진 인사말보다, 기억에 남은 답변 하나로 시작해보세요.
생각을 읽고 편지로 이어가는 소개팅, 프롤로그.

위 글은 운영자가 만든 편지 예시다. 이용 후기나 실제 연결 사례로 표시하지 않는다.

## 첫 참여자 모집과 운영

첫 모집은 한 지역에서 소개 조건이 맞는 20명 안팎으로 시작한다. 나이·지역·서로의 소개 선호를 함께 보고 한쪽에만 참여자가 몰리지 않도록 모집한다. 성별이나 나이의 구체적인 범위는 운영자가 실제 모집 가능한 사람을 확인한 뒤 정한다.

모집 문구:

> 사진보다 생각을 먼저 알아가는 소개팅 앱 프롤로그의 초기 참여자를 찾고 있어요. 질문에 답하고 소개 가능한 상대의 생각을 읽는 방식입니다. 초기에는 상대를 기다리는 시간이 있을 수 있어요. 첫 이용 뒤 좋았던 점과 막힌 부분을 짧게 들려주실 분을 기다립니다.

1. 첫날: 웹 체험·실제 가입·사진 업로드·문답 저장·편지까지 운영자 테스트 계정으로 확인한다.
2. 2~3일: 지인 소개와 참여 목적이 맞는 커뮤니티를 통해 첫 참여자를 직접 모집한다. 발송·게시 대상과 채널은 운영자가 정한다.
3. 4~5일: 소개를 받은 참여자에게 첫 답변, 상대를 기다린 경험, 편지에서 망설인 이유를 묻는다.
4. 6~7일: 실제 소개·답장 수와 인터뷰를 함께 보고 다음 모집 범위를 결정한다.

첫 편지 혜택과 연락처 교환 시점 변경은 후속 실험 후보다. 이번 코드에서는 요금·연락처 공개 규칙을 바꾸지 않았다. 먼저 편지 작성 시작 대비 전송·답장을 확인하고, 인터뷰에서 같은 장벽이 반복되면 한 가지씩 바꾼다.

## 측정과 판단

웹 빌드에 `PUBLIC_POSTHOG_KEY`를 설정하면 다음 익명 이벤트가 전송된다. 개인 API 키 대신 공개 프로젝트 토큰을 사용한다. 개발 서버·관리자 경로는 수집하지 않으며 브라우저의 추적 거부 설정을 따른다.

| 구간 | 이벤트·근거 | 확인할 것 |
| --- | --- | --- |
| 유입 | `web_landing_viewed` | 채널별 방문 세션 |
| 체험 | `web_preview_completed` | 체험을 실제로 선택한 세션 |
| 설치 의사 | `web_download_clicked`, `web_store_opened` | 체험 후 다운로드·스토어 이동 |
| 가입 | 앱 `onboarding_completed`, 서버 `ONBOARDED` | 사진·문답까지 완료한 계정 |
| 소개 | 서버 `PEER_AVAILABLE` | 소개가 실제로 가능한 계정 |
| 연결 | 편지 전송·답장·상호 연락처 교환 DB 집계 | 실제 상호 반응 |

웹 ID는 브라우저 세션 안에서만 유지된다. 웹 스토어 이동과 앱 가입을 같은 사람으로 자동 연결할 수 없으므로 웹→설치→가입 전환율로 합치지 않는다. 설치는 스토어 통계, 앱 사용은 계정 코호트로 각각 본다. 웹은 재방문·내부 테스트를 포함할 수 있으며, 앱·DB는 관리자·리뷰·테스트 계정을 제외한다.

답변 내용·선택값·전화번호·이메일·상대 계정 ID·전체 URL은 웹 분석으로 보내지 않는다. 채널 값은 `instagram`, `threads`, `community`, `partner`, `direct`, 캠페인은 `first_connection`만 구분하고 다른 값은 일반화한다.

광고 확대 판단은 클릭 수와 함께 가입 후 실제 소개와 답장이 반복되는지를 본다. 초기 표본에서는 숫자 하나를 성공률로 일반화하지 않는다.
