# 스토어 스크린샷 (v3)

`node store/v3/build.mjs` → `out/ios/*.png` (1320×2868), `out/android/*.png` (1080×1920)

## 왜 다시 만들었나

이전 스크린샷(`store/*.png`, `store/v2/`)이 낡아 보인 이유는 취향 문제가 아니라 두 가지였습니다.

**1. 지난 브랜드입니다.** 배경이 크림(`#F5EFE9` 계열)인데, 앱의 디자인 시스템은
차가운 중성 회색(`#F6F8FA`) + 테라코타 포인트 하나로 바뀌었습니다.
`design/README.md`에 "크림 바탕이던 시절에는…"이라고 적힌 그 시절의 그림입니다.
스토어에서 본 화면과 받은 앱이 다른 물건으로 보입니다.

**2. 실제 화면이 한 장도 없습니다.** 클립아트 아바타와 손그림 봉투를 올린 연출 그림이라
무엇을 하는 앱인지 알 수 없고, 버튼에 박힌 진한 드롭섀도가 연식을 그대로 드러냅니다.

## 어떻게 만드나

그림을 그리지 않습니다. **앱 코드의 pt 값을 그대로 옮겨 실제 화면을 재현**하고,
기기 틀에 넣어 헤드라인 한 줄을 얹습니다.

- `frame.css` — 판형(배경·헤드라인·기기), iOS/Play 두 판의 치수
- `screens.css` — 화면 조판. 값의 출처는 `mails.tsx` / `meetup-invitation.tsx`의 `StyleSheet`
- `build.mjs` — 패널 정의(문구·마크업)와 헤드리스 크롬 촬영

화면은 402pt 폭으로 짜고 마지막에 한 번만 확대합니다(iOS 2.5배, Play 1.865배).
`fontSize: 27`을 그대로 `27px`로 쓸 수 있어 조판이 앱과 어긋나지 않습니다.

> **앱 화면을 고치면 여기도 같이 고쳐야 합니다.** 값이 갈라지는 순간 이 스크린샷은
> 다시 '실제와 다른 그림'이 됩니다 — v2가 낡은 것과 같은 이유로요.

## 판형

| | 크기 | 비고 |
|---|---|---|
| iOS | 1320×2868 | 6.9″. 6.5″(1284×2778)가 필요하면 리사이즈해서 씁니다 |
| Play | 1080×1920 | 애플 판을 줄여 쓸 수 없습니다 — Play는 긴 변이 짧은 변의 2배를 넘으면 거부하는데 6.9″는 2.17배입니다 |

기기 틀도 판마다 다릅니다. Play 판에 다이내믹 아일랜드를 그리면 아이폰이 되므로
펀치홀 카메라로 바꿉니다.

## 다섯 장의 순서

검색 결과에는 앞 두세 장만 보입니다. "무엇을 하는 앱인가"와 "왜 다른가"를 먼저 둡니다.

1. **사진보다 생각이 먼저 닿아요** — 오늘의 문답과 내가 남긴 답
2. **답을 남기면, 한 사람** — 상대의 답이 먼저, 사진은 그 뒤에 오는 카드
3. **채팅 대신 편지 한 통** — 봉투로 도착하는 편지함
4. **연락처는 편지에 담아** — 열린 편지와 연락처 교환 규칙
5. **문답 밖에서 직접 만나요** — 오프라인 모임 초대장

## 사진

`store/personas/`의 페르소나 사진을 씁니다(앱 시드 계정과 같은 인물).
사람 사진이 들어가면 애플 심사에서 실제 인물로 오인될 소지가 없도록
생성 이미지임을 유지하고, 실제 유저 사진은 절대 쓰지 않습니다.
